## 1. Executive Summary & Purpose

Phase 016 upgraded the AEC evaluation architecture from static $H=18$ rollouts into a 4-tier macro-aware evaluation engine with pre-simulation boundary probing (`MacroRegimeTransitionDetector`), dynamic frozen V3 continuation (`V3ContinuationPolicy`), causally adaptive horizon expansion (`select_adaptive_horizon`), and zero-leakage state restoration (`snapshot_v3_state` / `restore_v3_state`).

This upgraded architecture successfully eliminated the catastrophic multi-thousand-dollar macro bifurcations of Phase 015:
- Canonical failure seed `249276` recovered from `-$39,455.00` to `-$2,523.00` (+93.6% loss reduction).
- Fresh pilot cohort (`249286..249295`, 20 mirror matches) recovered from `-$58,569.80` to `-$884.20` (+98.5% loss reduction).

However, the fresh pilot demonstrated that the quarantined Phase 015 opportunity mechanisms remain net-negative on average (`-$884.20`, 1W-9L-0T). The mandated goal of Phase 017 is to audit and attribute this residual negative delta without guessing or blindly adding new mechanisms.

In accordance with §6 of the Phase 017 specification, this document establishes a **comprehensive forensic inventory** of all telemetry instrumentation, data structures, schemas, and historical datasets produced in Phase 016, identifying existing fields and defining required extensions for the Phase 017 attribution ledger.

## 2. Inventory of Existing Phase 016 Telemetry Schemas

Phase 016 established rich, structured telemetry across five primary data classes.

### 2.1 `CandidateTelemetry` (`aec/integration/executor.py`)
Recorded per proposed candidate patch:
- **Identification**:
  - `patch_id: str`: Unique identifier of the candidate patch.
  - `mechanism_family: str`: Mechanism family (e.g., `AUTONOMOUS_TRANCHE_ORDER_SYNTHESIZER`, `DEPENDENCY_AWARE_MARKET_TIMING`).
- **Lifecycle Flags**:
  - `opportunity_detected: bool`: True if detected by Layer 1.
  - `patch_generated: bool`: True if compiled by PatchGenerator.
  - `patch_pruned: bool`: True if filtered by static pruning / feasibility.
  - `simulation_run: bool`: True if evaluated in shadow rollout.
  - `commit_decision: bool`: True if selected and committed.
- **Evaluation Quantities**:
  - `simulation_horizon: int`: Horizon evaluated ($H=6..120$).
  - `delta_money: float`: Projected money delta under simulation.
  - `delta_margin: float`: Projected margin delta under simulation.
  - `delta_route_cost: float`: Movement / labor route change.
  - `delta_dependency_completion: float`: Impact on downstream graph.
  - `delta_opponent_pressure: float`: Impact on opponent pressure state.
  - `delta_money_realized: float`: Realized cash at turn 0.
  - `delta_margin_realized: float`: Realized margin at turn 0.
  - `projected_asset_value: float`: Asset value projection.
  - `projection_status: str`: "REALIZED" vs "PROJECTED".
- **Safety & Rejection Attribution**:
  - `spatial_consistency_ok: bool`: True if worker coordinates matched.
  - `safety_pass: bool`: Passed all hard safety predicates.
  - `safety_rejection_reason: Optional[str]`: Exact safety or quarantine failure reason.
  - `economic_rejection_reason: Optional[str]`: Invalidation reason from WinModel.
- **Action Diffs**:
  - `baseline_action: Optional[Dict[str, Any]]`: Deep copy of baseline action.
  - `candidate_action: Optional[Dict[str, Any]]`: Deep copy of candidate action.
- **Mechanism Dependency & Causal Meta**:
  - `why_v3_did_not_do_this: Optional[str]`: Causal explanation of V3 omission.
  - `candidate_quantity: int`: Tranche unit quantity.
  - `candidate_reason: Optional[str]`: Structural anchor reason (`MINIMAL_TRANCHE`, `STORAGE_CLEARING`, etc.).
- **Macro-Aware Telemetry (Added in Phase 016)**:
  - `macro_escalated: bool`: Whether Tier 2 probe triggered escalation.
  - `macro_regime_type: str`: Enum string of macro regime (`CASH_CAPEX_GATE`, `BUDGET_GUARD_BLOCK`, etc.).
  - `macro_escalation_reason: Optional[str]`: Text rationale for escalation.
  - `first_divergence_turn: Optional[int]`: Step offset where candidate V3 continuation diverged from baseline V3 continuation.

### 2.2 `AECTelemetry` (`aec/integration/executor.py`)
Recorded per live game turn:
- `step: int`: Game turn step index ($0..719$).
- `decision: str`: "COMMIT", "BACKBONE", "ABSTAIN", or "FAIL_SAFE".
- `events_detected: List[str]`: List of detected event types.
- `opportunities_count: int`: Opportunities generated by OpportunityEngine.
- `opportunities_quarantined_count: int`: Quarantined opportunities intercepted.
- `quarantined_by_mechanism: Dict[str, int]`: Mechanism breakdown of quarantines.
- `candidates_count: int`: Candidate patches surviving to evaluation.
- `simulations_run: int`: Total forward simulations executed this turn.
- `committed_patch_id: Optional[str]`: ID of committed patch if committed.
- `committed_mechanism: Optional[str]`: Family of committed mechanism.
- `abstain_reason: Optional[str]`: Rationale for abstaining.
- `lifecycle: Dict[str, int]`: Turn counts for generated, quarantined, pruned, simulated, safety-rejected, economically-rejected, committed.
- `macro_escalations_count: int`: Number of candidate evaluations escalated to $H > 18$.
- `macro_escalated_by_regime: Dict[str, int]`: Breakdown of escalations by regime category.
- `candidates: List[CandidateTelemetry]`: Array of all candidate records.
- `latency_ms: Dict[str, float]`: Component execution times (`ir`, `event`, `opp`, `sim`, `safety`, `total`).

### 2.3 `SimulationOutcome` (`aec/counterfactual/simulator.py`)
Recorded per forward counterfactual evaluation:
- `candidate_final_money: float`, `baseline_final_money: float`, `delta_our_money: float`.
- `candidate_opp_final_money: float`, `baseline_opp_final_money: float`, `delta_opponent_money: float`.
- `delta_terminal_margin: float`: Total wealth delta ($W_{\text{cand}} - W_{\text{base}}$).
- `candidate_overflow_units: int`: Dropped/lost goods from shed saturation.
- `candidate_sold: Dict[str, int]`, `baseline_sold: Dict[str, int]`: Cumulative goods cleared.
- `intermediate_solvency_ok: bool`: True if cash/shed remained non-negative throughout rollout.
- `horizon: int`: Rollout depth executed.
- `spatial_consistency_ok: bool`, `desynchronization_reason: str`.
- `fidelity: str` ("VERIFIED", "PARTIAL", "FAILED"), `fidelity_reasons: List[str]`.
- `feed_security_ok: bool`, `feed_deficit_units: int`.
- `macro_escalated: bool`, `macro_regime_type: str`, `macro_escalation_reason: str`.
- `first_divergence_turn: Optional[int]`: First step where candidate policy diverged from baseline.
- `direct_intervention_effect: float`: Cash delta at turn 0 ($A$).
- `macro_induced_continuation_delta: float`: Downstream policy continuation delta ($B$).
- `executed_baseline_actions: Optional[List[Dict[str, Any]]]`: Exact trajectory of baseline actions.
- `executed_candidate_actions: Optional[List[Dict[str, Any]]]`: Exact trajectory of candidate actions under V3 continuation.

### 2.4 `MacroBoundaryProbeResult` (`aec/counterfactual/macro_detector.py`)
Recorded during Tier 2 pre-simulation boundary screening:
- `requires_escalation: bool`: True if boundary crossing or proximity detected.
- `regime_type: MacroRegimeType`: Identified macro regime.
- `reason: str`: Text explanation of the risk detected.
- `recommended_horizon: int`: Causal horizon computed to cover the policy divergence window ($H \in [18, 120]$).
- `earliest_divergence_step: int`: Anticipated step of policy bifurcation.
- `baseline_fingerprint: MacroRegimeFingerprint`: State fingerprint before action.
- `candidate_fingerprint: Optional[MacroRegimeFingerprint]`: Projected state fingerprint post-action.

### 2.5 `MacroRegimeFingerprint` (`aec/counterfactual/macro_detector.py`)
Deterministic 13-tuple capturing macro-relevant state:
- `step`, `day`, `cash`, `cash_bracket` (0 to 4).
- `quadrants_count`, `hands_count`, `has_animals`, `animal_counts`.
- `wheat_in_shed`, `total_shed_units`, `unlocked_shops`.
- `next_block_step` (`step % 72 == 0` milestone), `next_day_end_step` (`step % 24 == 23` milestone).

## 4. Telemetry Gap Analysis for Phase 017

While Phase 016 successfully instrumented turn-level and candidate-level telemetry, certain vital attribution metrics were aggregated into JSON summaries without persisting full candidate-level decision matrices to disk for offline query.

Specifically:
1. **Candidate Outcome Attribution Ledger (§7)**:
   - Need to persist every evaluated candidate into a structured record capturing:
     `[seed, seat, step, candidate_id, mechanism, local_cf_delta, long_horizon_delta, final_terminal_delta, macro_escalated, macro_regime, decision, reason]`.
2. **Decomposition Identity (§8)**:
   - Direct Intervention Effect ($A = \Delta_{\text{local}}$).
   - Macro-Induced Divergence Cost ($B = \Delta_{\text{macro}}$).
   - Downstream Residual ($C = \Delta_{\text{final}} - (A + B)$).
3. **Overblocking Audit (§9, §10)**:
   - Distinguishing candidates rejected because long-horizon delta was truly $< 0$ vs. candidates that were potentially $> 0$ under full continuation but rejected by conservative heuristics or short-horizon bounds.
4. **Seed-by-Seed Divergence Forensics (§14)**:
   - Investigating the causal chain on seeds with high divergence (e.g. Seed 249288 with 0 commits yet a paired margin difference, Seed 249292 worst loss `-$2,159.00`, and Seed 249291 win `+$54.00`).
