# PHASE022 COUNTERFACTUAL FIDELITY RED-TEAM (Independent Adversarial Audit)

**Date**: 2026-09-20
**Claim under attack**: "34 committed intervention traces audited against realized
match outcomes; MAE = $0.00, max discrepancy = $0.00, r = 1.0000; bit-exact
mathematical fidelity."

## 1. Verdict up front

**The MAE = $0.00 figure is a tautology, not a measurement.** The "realized"
value is assigned directly from the predicted value at evaluation time and is
never updated by any independent observation. Comparing them can only yield
zero. The claim "audited against realized match outcomes" is false.

## 2. Proof from source

### 2.1 The assignment (prediction copied to "realized")

`aec/evaluation/win_model.py`, main return path (lines 373-374):

```python
delta_money_realized=delta_money,
delta_margin_realized=delta_margin,
```

and the spatial-desync early-return path (lines 167-168): identical copy.
`delta_money`/`delta_margin` are the simulator outputs
(`outcome.delta_our_money`, `outcome.delta_terminal_margin`, lines 137-138).

### 2.2 No post-hoc update exists

Repo-wide search for writers of `delta_money_realized` finds exactly two:

- `aec/evaluation/win_model.py` (the copy above),
- `aec/integration/executor.py:680-681`, which copies `eval_res.*` into
  candidate telemetry (a second copy of the same number).

No code path ever overwrites these fields with an observed continuation outcome.
`projection_status="REALIZED"` is likewise a constructor default, not a
measurement outcome.

### 2.3 The audit compares the value to itself

`scripts/run_phase022_consolidation.py:418-434`:

```python
pred_delta = c.get("delta_money", 0.0)
realized_delta = c.get("delta_money_realized", pred_delta)  # fallback copy
diff = abs(pred_delta - realized_delta)  # identically 0.0
```

The mandated red-team check (`c.get("delta_money_realized", pred_delta)`)
confirms the fallback exists; worse, the primary value is itself the copy, so
the fallback never even matters. The function imports `CounterfactualSimulator`
and `CoupledPatch` (lines 398-399) but never uses them: **the "audit" performs
zero independent re-simulation.**

### 2.4 Artifact confirmation

All 34 committed candidates in `results/phase022_decision_traces.json` satisfy
`delta_money == delta_money_realized` (34/34, auditor-verified). Only 20 of 34
samples were persisted to `phase022_consolidation.json` (`samples[:20]`),
without seat identifiers, so two mirror-match samples share identical
(seed, step) keys.

## 3. What the evidence actually supports

| Statement | Status |
| --- | --- |
| "Predicted and stored realized fields agree on 34 commits" | TRUE but vacuous |
| "Realized deltas were measured from independent realized continuations" | FALSE |
| "MAE = $0.00 validates the simulator" | FALSE (circular) |
| "The market simulator replicates sim.hpp lockstep clearing" | Plausible architecture, UNVALIDATED by this number |
| "Zero physical footprint implies low divergence risk for timing" | Reasonable engineering argument, not empirical proof |

A genuine fidelity audit would require an independent replay: re-execute the
recorded baseline action and candidate action from the recorded state through
an independent engine instance and compare ledgers. The repository contains an
unused `aec/counterfactual/parity_harness.py` that gestures at this idea; it is
not wired into the audit and imports the Windows-only `kagsim`.

## 4. Secondary finding: predicted deltas do not explain match deltas

Example: seed 249378 won +$103 on two commits with predicted deltas $0 and
+$36 (sum $36 != $103); seed 249395 won +$115 on commits predicting +$15 and
+$100 (sum $115 -- exact here, but coincidental: predictions are
horizon-limited simulation deltas, match deltas are 719-step equilibrium
outcomes including opponent-price effects). The report's "Impact on Match"
attributions ("drove treatment from $100,141 to $100,244") present match-level
deltas as caused by single commits without any decomposition. No per-commit to
match-delta reconciliation exists in the artifacts.

## 5. Classification

**Counterfactual fidelity: FAIL** (as an empirical validation claim). The
arithmetic is correct and the underlying simulator design may be sound, but
MAE = $0.00 is generated by construction and must not be presented as evidence
of independent validation. The section must be rewritten as an architecture
description with the empirical claim withdrawn.
